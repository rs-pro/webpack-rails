# GitLab CI/CD Setup for rs-webpack-rails

## Overview

The `.gitlab-ci.yml` configuration provides automated testing and quality checks for the webpack-rails gem on GitLab.com's public CI infrastructure.

## Pipeline Stages

### 1. Setup Stage
- **setup:dependencies** - Installs and caches Ruby gems and Node.js packages

### 2. Test Stage
- **test:ruby-3.3** - Runs full test suite on Ruby 3.3
- **test:ruby-3.4** - Runs full test suite on Ruby 3.4
- **test:webpack-compile** - Verifies webpack compilation with .digested extension
- **test:generator** - Tests `rails generate webpack_rails:install` command
- **test:rails-7** (optional) - Tests with Rails 7.x specifically
- **test:rails-8** (optional) - Tests with Rails 8.x specifically

### 3. Quality Stage
- **quality:rubocop** - Runs RuboCop linter
- **quality:bundle-audit** - Checks for security vulnerabilities
- **pages** - Publishes coverage report to GitLab Pages

### 4. Release (on tags)
- **release:gem** - Builds gem file for release

## Required CI/CD Variables

### For Basic Testing
No variables required! The pipeline works out of the box.

### For RubyGems Publishing (Optional)
If you want to automatically publish to RubyGems on tags:

1. Go to Settings → CI/CD → Variables
2. Add variable:
   - **Key**: `RUBYGEMS_API_KEY`
   - **Value**: Your RubyGems API key
   - **Type**: Variable
   - **Protected**: Yes
   - **Masked**: Yes

3. Uncomment the gem push section in `.gitlab-ci.yml`:
   ```yaml
   - |
     if [ -n "$RUBYGEMS_API_KEY" ]; then
       mkdir -p ~/.gem
       echo ":rubygems_api_key: ${RUBYGEMS_API_KEY}" > ~/.gem/credentials
       chmod 0600 ~/.gem/credentials
       gem push *.gem
     fi
   ```

## Caching Strategy

The pipeline caches:
- **Ruby gems** - `vendor/bundle` (keyed by Gemfile.lock)
- **Node modules** - `spec/dummy/node_modules` (keyed by package-lock.json)
- **npm cache** - `.npm` directory

This significantly speeds up subsequent pipeline runs.

## Running Specific Jobs Locally

### Run tests locally (simulating CI):
```bash
# Install dependencies
bundle install
cd spec/dummy && npm install && cd ../..

# Run tests
bundle exec rspec

# Run rubocop
bundle exec rubocop
```

### Test webpack compilation:
```bash
cd spec/dummy
npm run build
ls -la public/webpack/*.digested.js
```

### Test generator:
```bash
rails new /tmp/test_app --skip-bundle --asset-pipeline=propshaft
cd /tmp/test_app
echo "gem 'rs-webpack-rails', path: '$(pwd)'" >> Gemfile
bundle install
bundle exec rails generate webpack_rails:install
```

## Troubleshooting

### Chrome/Cuprite Issues
If browser tests fail with Chrome errors:
- Check Chrome installation in before_script
- Verify CHROME_PATH environment variable
- Review Cuprite configuration in spec/rails_helper.rb

### Cache Issues
If dependencies aren't cached properly:
- Check cache key configuration
- Verify Gemfile.lock and package-lock.json exist
- Try clearing pipeline cache: CI/CD → Pipelines → Clear runner caches

### Node.js Version Issues
The pipeline installs Node.js 20 LTS via NodeSource. If you need a different version:
```yaml
- curl -fsSL https://deb.nodesource.com/setup_18.x | bash -
```

### Test Failures
1. Check the specific failing job in GitLab CI
2. Review the job log for error details
3. Download artifacts to inspect coverage/test reports
4. Run the same command locally to reproduce
